# 中医医案知识图谱

**TCM Medical Case Knowledge Graph**

本项目面向中医临床医案的结构化整理与知识关联展示。以医案文献（DOCX）为输入，利用大语言模型辅助提取患者信息、四诊表现、病证、治法及方药等内容，经过术语规范化和人工复核，生成知识图谱数据，并为 Neo4j 导入与查询提供支持。

## 处理流程

```text
DOCX 医案文献
    ↓
文档切分与人工选案
    ↓
来源映射与医案编号核对
    ↓
GPT-5.5 结构化信息抽取（JSON）
    ↓
术语规范化、审查建议与人工复核
    ↓
节点表 / 关系表 / 三元组表（CSV）
    ↓
Neo4j 导入文件与 Cypher 查询
```

代码按照六个阶段组织：

| 阶段 | 核心任务 | 主要产物 |
| --- | --- | --- |
| `01_document_processing` | DOCX 切分与预览 | 拆分结果、预览表 |
| `02_case_preparation` | 人工选案、编号与来源核对 | 医案文本、来源映射 |
| `03_information_extraction` | GPT-5.5 字段抽取 | 医案 JSON、调用配置与日志 |
| `04_data_review` | Excel 整理、规范化与复核 | 待审及确认后的工作簿 |
| `05_graph_construction` | 按 Schema 生成图谱 | 节点表、关系表、三元组表 |
| `06_neo4j_export` | CSV 校验与导入准备 | Neo4j 导入包、Cypher 文件 |

各阶段的主要脚本及产物分别位于 `pipeline/` 对应目录；历史流程存放在 `archive/`，不属于当前主线。

## 图谱设计

图谱以**医案**为组织中心，关联患者、症状体征、舌象、脉象、辅助检查、中医病名、西医病名、证型、治则治法、方剂、中药和疗效转归，共 **13 类节点**。节点、关系和属性使用中文命名，具体定义见 `pipeline/05_graph_construction/kg_schema.py`。

典型关联包括：

```text
医案 ──具有症状体征──> 症状体征
医案 ──辨证为──────> 证型
医案 ──采用治法────> 治则治法
医案 ──使用方剂────> 方剂 ──包含中药──> 中药
```

当前设计不额外建立“处方”节点；方剂与中药作为可复用概念节点。图谱可用于探索医案的辨证论治关联，以及症状—医案—方剂、病名—证型等查询路径。

## 数据与质量控制

原始医案经人工筛选后独立编号，并保留来源映射。信息抽取采用预设字段模板；模型输出先转为工作簿，再进行字段检查、术语规范化与人工核对。**自动审查建议不等于人工确认**，也不直接代表医学准确性已得到验证。

公开仓库以流程代码为主。原始医案、实际模型响应和人工复核材料不默认公开；使用外部数据前需自行核查授权、隐私和脱敏要求。

## 运行与验证

运行环境涉及 Python、Node.js 与 Neo4j；Python 依赖见 `requirements.txt`。信息抽取通过兼容 Chat Completions 的接口调用，当前请求模型标识为 `gpt-5.5`；使用时需自行配置 `API_KEY` 等接口参数。各阶段按 `pipeline/01` 至 `06` 的顺序执行，实际运行应使用独立批次目录保存结果。

目前已使用虚构样本和模拟接口验证六阶段脚本衔接、图谱 CSV 校验及导入包生成；选案表与 50 份 Case 文本已通过来源核对。上述测试**不包含**真实模型接口、医学人工复核或 Neo4j 数据库实际导入验证。生成导入包不等于已完成数据库导入。

## 当前范围

本版本重点展示医案信息抽取、结构化整理和知识图谱数据组织。中药剂量、单位虽在关系结构中预留字段，但现有构图流程尚不能保证完整回填；复杂合方、跨医案用药差异和多诊次关联也未作为本版本的完整支持能力。后续将根据数据复核与图谱查询结果逐步完善。
